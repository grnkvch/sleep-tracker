# Решения

## D-001. Одна кодовая база

Общий контент хранится в `ru.mdx`; launch-профили содержат только отличия CTA, канала и hero-shell. Runtime-переключателя нет.

## D-002. Preview по умолчанию

Пока продуктовые URL и обязательные факты не подтверждены, любая обычная сборка закрыта от индексации. CTA ведёт к продуктовому примеру внутри страницы и не имитирует запуск готового продукта.

## D-003. Продуктовая графика

Мокапы, таймлайны, история и иконки реализованы HTML/CSS/inline SVG. Это сохраняет читаемый текст, адаптивность и нулевую зависимость от растровых hero-изображений.

## D-004. Буквальная геометрия

Пять секций используют пропорциональные `min-block-size` от общего responsive-токена `--section-unit`: `5 / 15 / 20 / 40 / 20`. Внутри нет spacer-элементов, обрезания или скрытого текста; пространство занято реальными модулями и распределяется CSS layout. Playwright измеряет фактические DOM-высоты на пяти viewport для трёх профилей.

Если новая редакция текста начинает превышать минимальную высоту секции, тест показывает фактическое отклонение и требует перекалибровки модулей, padding или gap.

## D-005. Без провайдера

Сборка заканчивается обычной статикой в `dist/<profile>/`. Аналитика, хостинг, CMS и CI/CD не выбраны.

## D-006. GitHub Pages только для просмотра preview

По отдельному запросу владельца hybrid-preview публикуется через GitHub Pages. Это не выбор production-хостинга: сборка остаётся `noindex`, а продуктовые CTA используют внутренний demo-fallback до подтверждения реальных URL.
